# 05 — Linux Security

[← Back to the English contents](README.md) | [Magyar változat](../hu/05-linux-security.md)

## Introduction

Linux is widely used on servers, cloud platforms, network devices, and security systems. A SOC analyst may therefore investigate many alerts and logs generated by Linux systems.

This chapter explains the basic concepts in a beginner-friendly way. The aim is not to provide advanced Linux administration training. The focus is on where useful evidence may appear and which simple questions can support an investigation.

## 1. What Is Linux?

Linux is an open-source kernel that forms the core of many operating systems.

The word Linux is also commonly used for complete operating systems such as:

- Ubuntu
- Debian
- Fedora
- Red Hat Enterprise Linux
- Kali Linux
- Rocky Linux
- AlmaLinux

These are called Linux distributions.

Different distributions are similar in many ways, but commands, package management, and log locations may differ.

## 2. Why Linux Matters in a SOC

Linux systems often run:

- web servers
- databases
- file servers
- cloud services
- containers
- network services
- security tools

Security-relevant events may include:

- successful and failed logons
- new user accounts
- permission changes
- `sudo` activity
- services starting or stopping
- scheduled tasks
- new or modified files
- network connections
- software updates
- signs of vulnerability exploitation

## 3. Terminal and Shell

A **terminal** is an interface used to enter text commands.

A **shell** is the program that interprets those commands.

Common shells include:

```text
bash
zsh
sh
```

Example:

```bash
pwd
```

This displays the current directory.

Terminal activity is not suspicious by itself. Administrators and users regularly work from the command line.

## 4. Users and Groups

Every Linux process and file is associated with a user and group.

Common account types include:

- standard users
- users with administrative access
- service accounts
- the root user

The **root** account has the highest level of access.

A simple comparison is a master key that can open almost every door.

This makes root activity particularly important during a security investigation.

Useful commands:

```bash
whoami
who
groups
```

## 5. What Is sudo?

The `sudo` command allows an authorised user to run a command with elevated privileges.

Example:

```bash
sudo apt update
```

On Ubuntu or Debian, this updates the package list.

Using `sudo` is not automatically suspicious. Administrators use it regularly.

It may deserve attention when:

- an unusual user runs it
- it occurs at an unexpected time
- it is followed by a dangerous or rare command
- several failed attempts appear
- a service account requests administrative access

Ubuntu documentation recommends using elevated privileges only when they are needed.

The Hungarian National Cyber Security Center has also reported vulnerabilities affecting `sudo`, showing that flaws in a basic system tool can create serious risk.

## 6. Files and Permissions

Linux files and directories have permissions.

The three basic permissions are:

- `r` = read
- `w` = write
- `x` = execute

They apply to:

- the owner
- the group
- everyone else

Example:

```text
-rwxr-x---
```

This means:

- the owner can read, write, and execute
- the group can read and execute
- other users have no access

Useful command:

```bash
ls -l
```

Security-relevant examples include:

- a sensitive file becomes writable by everyone
- the owner of a configuration file changes
- a file becomes executable
- an unknown file appears in a system directory

## 7. Important Directories

| Directory | Simple meaning |
|---|---|
| `/home` | user files |
| `/etc` | system and application configuration |
| `/var/log` | many system logs |
| `/tmp` | temporary files |
| `/usr/bin` | many executable programs |
| `/bin` | basic commands |
| `/root` | root user's home directory |
| `/proc` | process and kernel information |

The `/tmp` directory may be interesting because many users can write temporary files there. Legitimate programs use it, but attackers may also place files there.

## 8. Linux Logs

Log locations may differ between distributions.

Common examples include:

```text
/var/log/auth.log
/var/log/secure
/var/log/syslog
/var/log/messages
```

### auth.log or secure

These often contain authentication events such as:

- successful SSH logons
- failed logons
- `sudo` use
- user switching

Ubuntu and Debian commonly use `/var/log/auth.log`.

Red Hat based systems commonly use `/var/log/secure`.

### syslog or messages

These may contain general system events such as:

- service errors
- system messages
- hardware events
- application messages

Always check the documentation for the distribution being investigated.

## 9. journalctl

Modern Linux systems often use `systemd-journald` to collect logs.

The `journalctl` command can query these records.

All available entries:

```bash
journalctl
```

Recent entries:

```bash
journalctl -n 20
```

Logs for one service:

```bash
journalctl -u ssh
```

Events from the current boot:

```bash
journalctl -b
```

Error-level events:

```bash
journalctl -p err
```

Microsoft Azure Linux documentation also recommends `journalctl` for querying kernel, service, and application events.

## 10. SSH

**SSH**, or Secure Shell, provides encrypted remote access.

It commonly uses port 22.

Example:

```bash
ssh user@server.example
```

SSH is a legitimate administration tool.

Activity may deserve attention when:

- many failed logons occur
- connections arrive from an unknown external address
- someone attempts to log in as root
- a successful logon occurs at an unusual time
- an unknown program starts after the logon
- a new key appears in `authorized_keys`

Ubuntu documentation highlights the importance of correct permissions on the `authorized_keys` file.

## 11. Processes

A process is a running program or part of a program.

View processes:

```bash
ps aux
```

Interactive view:

```bash
top
```

If installed:

```bash
htop
```

A process may deserve investigation when:

- it has an unusual name
- it runs from a temporary directory
- it uses a large amount of CPU
- it connects to an unknown external address
- it runs as root
- its name imitates a system process

High CPU use alone does not prove malicious activity. It may also result from a software problem or normal workload.

## 12. Services and systemctl

Many modern Linux systems use `systemd` to manage services.

View service status:

```bash
systemctl status ssh
```

List running services:

```bash
systemctl --type=service --state=running
```

Start a service:

```bash
sudo systemctl start ssh
```

Enable a service at boot:

```bash
sudo systemctl enable ssh
```

Beginners should mainly use read-only commands. Stopping or changing a service may cause system problems.

## 13. Cron and Scheduled Tasks

**Cron** runs commands and programs at defined times.

It is similar to Task Scheduler in Windows.

List the current user's cron jobs:

```bash
crontab -l
```

Example:

```text
0 2 * * * /home/user/backup.sh
```

This starts `backup.sh` every day at 02:00.

Cron is a legitimate system feature.

Attackers may also use it to:

- restart a program regularly
- maintain persistence after reboot
- delay execution

A cron job may deserve attention when:

- it starts an unknown script
- it runs a program from `/tmp`
- it downloads content from the internet
- it contains encoded or unreadable commands

## 14. Packages and Updates

Linux distributions use package managers to install and update software.

Ubuntu and Debian commonly use:

```bash
sudo apt update
sudo apt upgrade
```

Red Hat based systems commonly use:

```bash
sudo dnf update
```

Updates are important because they may fix security vulnerabilities.

The Hungarian National Cyber Security Center regularly publishes warnings about Linux vulnerabilities affecting the kernel, `sudo`, and other important components.

## 15. Simple Investigation Example

The logs show:

```text
01:42 — several failed SSH logons
01:47 — successful logon from an external IP
01:49 — sudo activity
01:51 — a new cron job was created
01:52 — connection to an unknown external address
```

Together, these events are more meaningful than they would be separately.

A beginner analyst may review:

1. which account was used
2. whether the source IP is known
3. whether the user was allowed to use `sudo`
4. which command was executed
5. what the new cron job runs
6. which process created the network connection
7. whether files changed
8. whether similar activity appears on other servers

The goal is to build a clear timeline.

## 16. Useful Mostly Read-Only Commands

```bash
whoami
who
id
groups
ls -l
ps aux
ss -tulpen
journalctl -n 20
systemctl --type=service --state=running
crontab -l
```

Use these commands only on systems you own or are authorised to examine.

## 17. Key Points for Beginners

- Root is the highest-privileged Linux account.
- `sudo` may temporarily provide elevated access.
- File permissions define who can read, write, or execute a file.
- Authentication logs are important for investigating logons.
- `journalctl` is a central log-query tool on many modern Linux systems.
- SSH is a legitimate remote administration tool, but attackers may also target it.
- Cron and services are normal features that may also be used for persistence.
- A sequence of related events is often more useful than one isolated log entry.
